# R2V Task Offloading Simulator

A discrete-event simulator for **RSU-to-Vehicle (R2V) Task Offloading** in Vehicular Fog Computing (VFC) environments. Built to model and evaluate the performance of an RSU that opportunistically offloads deadline-constrained computational tasks to passing vehicles.

---

## What This Simulates

The scenario is straightforward: an isolated RSU sits along a road. It receives computational tasks from nearby users and IoT devices, buffers them in a finite queue, and tries to offload them to passing vehicles before their deadlines expire. Vehicles have different speeds, processing capacities, and cooperativeness levels — so not every vehicle that passes by is actually useful.

The simulator captures all of this stochastically and measures how well the system performs under different conditions.

### The System Model

- **Vehicles** arrive following a Poisson process with a configurable arrival rate. Each vehicle's speed is drawn from a truncated Normal distribution (based on real free-flow traffic models), and its processing capacity is drawn uniformly from a configurable range.
- **Tasks** also arrive following a Poisson process. Each task has a randomly assigned size (in instructions) and a deadline drawn from a truncated exponential distribution.
- The **RSU** holds a finite buffer (M/M/1/B queue). When the buffer is full, newly arriving tasks are dropped. When a vehicle arrives, the RSU checks whether the Head-of-Line (HoL) task can be released to that vehicle — meaning the vehicle has enough capacity and residence time to complete the task before leaving the RSU's range.
- A vehicle is only useful if it is **cooperative** (controlled by the cooperation probability `pc`) and **capable** (its remaining processing capacity can handle the task within its residence time in the RSU's range).

---

## Key Features

### Scheduling Policies
Three scheduling disciplines are implemented, each determining the order in which tasks sit in the RSU's buffer:

- **FCFS (First Come First Served)** — tasks are served in the order they arrive. Simple but deadline-agnostic.
- **EDF (Earliest Deadline First)** — tasks with shorter deadlines are served first. Prioritizes urgency.
- **STF (Shortest Task First)** — tasks with smaller sizes are served first. Prioritizes tasks that are quickest to offload.

### Release Modes
For each scheduling policy, two release modes are supported:

- **Single Release (SR)** — the RSU offloads at most one task per vehicle arrival.
- **Bulk Release (BR)** — the RSU offloads as many tasks as the vehicle can handle in one go, exploiting the vehicle's full available capacity.

### Performance Metrics
The simulator tracks and outputs the following QoS metrics:

| Metric | Description |
|--------|-------------|
| `pr` | **Task Release Probability** — fraction of release opportunities that resulted in a successful offload |
| `pa` | **Task Admission Probability** — fraction of arriving tasks that were admitted into the buffer |
| `pe` | **Deadline Expiry Probability** — fraction of admitted tasks that expired before being released |
| `Ts` | **Mean Service Time** — average time a task spends at the Head-of-Line before being released |
| `Nt` | **Mean Number of Tasks in System** — average buffer occupancy over time |
| `Qt` | **Mean Buffering Delay** — average time a task spends waiting in the buffer (via Little's Law) |

### Parameter Sweeps
The simulator supports sweeping four different parameters, each producing a separate results file:

- **`pc`** — cooperation probability (0 to 1)
- **`μv`** — vehicle arrival rate (with corresponding speed distributions from real traffic data)
- **`λt`** — task arrival rate
- **`Cmax`** — maximum per-vehicle processing capacity

## How to Run

### Prerequisites

**Java (JDK 8 or higher)**
- Download from [https://www.oracle.com/java/technologies/downloads/](https://www.oracle.com/java/technologies/downloads/) or install OpenJDK.
- Verify installation: `java -version`

**MATLAB (for plotting)**
- Required only if you want to generate plots from the results.
- Any recent MATLAB version works (R2019b or later recommended).
- If you don't have MATLAB, the raw results are still available as `.txt` files in the `Results/` folder.

---

### Running on macOS / Linux

**1. Clone the repository**
```bash
git clone https://github.com/mariamelwirish/rsu-to-vehicle-task-offloading-simulator
cd rsu-to-vehicle-task-offloading-simulator
```

**2. Create the Results directory if it doesn't exist**
```bash
mkdir -p Results
```

**3. Compile all Java files**
```bash
javac src/*.java -d out/
```

**4. Run the simulator**
```bash
java -cp out/ Driver
```

The simulation will start printing event logs to the console and write results to the `Results/` folder when done.

---

### Running on Windows

**1. Clone the repository**

Either use Git Bash:
```bash
git clone https://github.com/mariamelwirish/rsu-to-vehicle-task-offloading-simulator
cd rsu-to-vehicle-task-offloading-simulator
```
Or download the ZIP from GitHub and extract it.

**2. Create the Results directory**

In Command Prompt:
```cmd
mkdir Results
```

**3. Compile**
```cmd
javac src\*.java -d out\
```

If `out/` doesn't exist yet:
```cmd
mkdir out
javac src\*.java -d out\
```

**4. Run**
```cmd
java -cp out\ Driver
```

---

### Running in an IDE (IntelliJ / Eclipse / VS Code)

If you prefer an IDE:

1. Open the project folder as a Java project.
2. Make sure all `.java` files in `src/` are included in the source root.
3. Set `Driver.java` as the main class.
4. Create a `Results/` folder in the project root if it doesn't exist.
5. Run `Driver.java`.

## Configuring the Simulation

All configuration is done in `Driver.java`. Open it and you'll see the main parameters at the top:

```java
static double[] vehicleArrivalRates = {0.1, 0.125, 0.15, ...};
static double[] avgVehicleSpeeds    = {45, 43.54, 41.95, ...};
static double[] stdVehicleSpeeds    = {13.5, 13.062, 12.585, ...};
static long maxTaskProcessingCapacities = 800_000_000L;
```

The vehicle speed and arrival rate arrays are paired — each index corresponds to a traffic scenario based on real free-flow traffic data.

### Choosing What to Vary

In the `main` method, uncomment whichever sweep you want to run:

```java
// Vary cooperation probability pc
for (double pc = 0.01; pc <= 1; pc += 0.1) { ... }

// Vary vehicle arrival rate μv  ← currently active
for (int i = 0; i < vehicleArrivalRates.length; i++) { ... }

// Vary task arrival rate λt
for (double i = 0.09; i <= 0.2; i += 0.01) { ... }

// Vary max processing capacity Cmax
for (long i = 300_000_000L; i <= 800_000_000; i += 100_000_000L) { ... }
```

Only one sweep should be active at a time (the others should be commented out).

### Changing the Scheduling Policy and Release Mode

In `Simulator.java`, find this line in the `start()` method:

```java
rsu = new RSU(rsuBufferCapacity, rsuCoverageRange, RSU.SchedulingPolicy.FCFS, false);
```

- First argument after coverage range: `RSU.SchedulingPolicy.FCFS`, `.EDF`, or `.STF`
- Last argument: `false` for Single Release, `true` for Bulk Release

## Reading the Results

After running, the `Results/` folder will contain `.txt` files — one per parameter sweep:

| File | Contents |
|------|----------|
| `pc.txt` | `pc, pr` |
| `mu.txt` | `μv, pr, Ts, pa, pe` |
| `lambda.txt` | `λt, Nt, Qt` |
| `c_max.txt` | `Cmax, pr` |

Each file has a header row followed by one data row per simulation run.

---

## Generating Plots (MATLAB)

Once you have results, open MATLAB, navigate to the project root directory, and run:

```matlab
plot_pc
```

The script automatically:
- Reads all `.txt` files from the `Results/` folder
- Plots each metric as a function of the varied parameter
- Saves all plots as `.png` files in the `Plots/` folder
- Opens an interactive tabbed figure window showing all plots

No configuration needed — it works generically with whatever files are in `Results/`.

## Simulation Parameters

These are the default values used in the simulator, consistent with the paper being reproduced:

| Parameter | Value | Description |
|-----------|-------|-------------|
| Buffer capacity `B` | 50 tasks | Maximum RSU queue size |
| Coverage range `CR` | 1000 m | RSU road coverage |
| Min vehicle speed | 10 km/h | Lower bound of speed distribution |
| Max vehicle speed | 50 km/h | Upper bound of speed distribution |
| Min task size | 10⁷ instructions | Lower bound of task size |
| Max task size | 5×10⁹ instructions | Upper bound of task size |
| Task deadline range | [0, 50] seconds | Truncated exponential distribution |
| Min processing capacity | 10⁷ inst/s | Lower bound per vehicle |
| Max tasks per run | 100,000 | Simulation stopping condition |
| RNG seed | 12345 | Fixed seed for reproducibility |

---

## Notes

- Console output is verbose by default — it prints every vehicle and task event. For long runs, you may want to redirect output to a file: `java -cp out/ Driver > simulation_log.txt`
- The RNG seed is fixed at `12345` in `Simulator.java` for reproducibility. Change it if you want different random realizations.
- Results files are appended across runs of the same sweep type within a session. If you re-run, delete the old files in `Results/` first to avoid mixing results.
